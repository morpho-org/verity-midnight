# Agent notes

Follow `README.md` for the proof task and edit rules.

If the task is about a model generated by `solidity_import`, read
`SOLIDITY_IMPORT.md` before your first proof attempt. It explains how to run
an imported body symbolically without exhausting memory, and the prebuilt
`ProofKit` lemmas (`import ProofKit`) that do it.

## Memory and Lean commands

The container has about 15 GB of memory in total. Each Lean process is capped
at `LEAN_MEMORY_MB` (default 6144): a runaway proof fails with `excessive
memory consumption detected`. Exit status 137 means the process was killed for
running out of memory, not a Lean error. Run Lean commands through `leanrun`
(`leanrun Midnight/Lemmas/Foo.lean`, `leanrun lake build X`), which reports
exit status, peak memory and wall time even when output is piped.

## Scratch files

Keep scratch and probe files under `Midnight/` (for example
`Midnight/Scratch.lean`), not elsewhere in the workspace; the host reports
files left outside `Midnight/`. `lake build` builds every module under
`Midnight/`, so delete scratch modules, or make sure they compile, before
running `./check/check_proof.sh`.

## Lean diagnostics MCP (required)

lean-lsp MCP is **required** for this task. Use `lean_diagnostic_messages`,
`lean_goal`, `lean_hover_info`, and `lean_local_search` for compiler feedback.
These do not replace `./check/check_proof.sh`.

`scripts/lean-mcp.sh` launches pinned `lean-lsp-mcp` from `/opt/lean-mcp` (image)
or `.lake/lean-mcp` (fallback). Cursor loads it from `.cursor/mcp.json`.
For Codex, the host launcher writes `/root/.codex/config.toml` with the same
launcher and `required = true`; the monitor has a separate home without MCP.

### If MCP is unavailable — stop immediately

Do **not** continue the proof with shell-only Lean. Terminate the session:

1. Write a one-line reason to `out/mcp-unavailable` (create `out/` if needed).
2. Stop; do not edit `Midnight/Proof.lean` further.

The host treats `out/mcp-unavailable` as failure (exit code **91**).

Optional smoke test:

```sh
/opt/lean-mcp/bin/python scripts/check-lean-mcp.py
```

Preflight (also run by `run-experiment.sh` before the agent):

```sh
sh scripts/require-lean-mcp.sh
```

### Interactive debug

MCP config is `.cursor/mcp.json` (absolute `/work/scripts/lean-mcp.sh` — the CLI
does not expand `${workspaceFolder}`). In a fresh container:

```sh
sh scripts/require-lean-mcp.sh
agent --force --approve-mcps --workspace /work
# Codex (AGENT_BACKEND=codex ./shell.sh <run-id>):
codex --cd /work --dangerously-bypass-approvals-and-sandbox
```

`--approve-mcps` auto-approves servers for that agent session; `mcp enable`
persists approval in the container home (lost when the container exits).
